# Долгое подключение AmneziaVPN на Windows

> **KillSwitch и переподключение:** оптимизация маршрутов не обеспечивает защиту
> до запуска VPN. Теперь updater откладывает применение изменённого списка при
> включённом KillSwitch и работающей Amnezia. Подробности и разовое применение —
> [KillSwitch на Windows](windows-killswitch.md).

Исследованный сценарий AmneziaVPN 5.0.1.5: большие исключения сайтов и
меняющаяся локальная сеть Hyper-V. Уменьшение списка пока не подтверждено как
полное исправление: повторная проверка обнаружила расхождение между записанным
планом и тем, что реально загружает клиент.

## Что показали логи

В исследованной попытке клиент показал подключение через **71,294 секунды**.
Ответ на VPN-рукопожатие уже был получен примерно через 18,5 секунды; затем
прошло ещё **53,796 секунды** до сообщения `connected` в GUI.

Служба обработала **3408 уведомлений об изменении маршрутов** и столько же
ошибок `Failed to update route: 5010`, повторно захватывая один broadcast-адрес
виртуальной локальной сети. В сохранённых исключениях находилась прежняя
подсеть Hyper-V, а на интерфейсе уже была другая. Поэтому ожидание перед вводом
пароля могло менять порядок событий, но само по себе не исправляло маршрутизацию.

Код 5010 означает «объект уже существует»:
[описание Microsoft](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--4000-5999-).
В [WindowsRouteMonitor версии из логов](https://github.com/amnezia-vpn/amnezia-client/blob/7d4f3e0f5/client/platforms/windows/daemon/windowsroutemonitor.cpp)
уведомления ставятся в очередь Qt по одному. При обработке пересматривается
таблица маршрутов; локальные маршруты, не покрытые исключениями, клонируются
в VPN. Неудачная попытка клонирования не запоминается и повторяется при
следующем уведомлении. Тысячи накопленных событий могут задерживать обработку
сообщения об успешном подключении. Это согласуется с измеренным таймлайном.

Гипотезы о CrossPaste и NetLimiter эти логи не подтверждают. Отключать их,
Hyper-V или killswitch для применения этого исправления не требуется.

### Повторная проверка 2026-09-12

Установщик записал 592 CIDR-записи и успешно прочитал их обратно. Независимое
чтение через настоящий Qt QSettings также вернуло 592 записи без доменных ключей.
Однако следующая попытка в журнале загрузила прежние **3409 исключений**, включая
`/999999`. Было 6810 уведомлений о смене маршрутов, 3406 ошибок 5010 и 13616
ошибок 1168. Это не подтверждает применение нового списка в работающем клиенте.

Дополнительное чтение через уже открытый приложением раздел реестра вернуло
3902 старые записи; новое открытие того же пути из диагностического процесса
вернуло 592. Причина расхождения представлений реестра пока не установлена.
Повторные перезапуски без подтверждения результата не являются исправлением.
Поле `effective_route_count` описывает подготовленный план, а не измеренную
активную таблицу; `active_routes_verified: false` явно фиксирует это ограничение.
Для WireGuard восстановление теперь ждёт подтверждённого рукопожатия демона,
поскольку работающая служба и поднятый адаптер появляются раньше соединения.

## Что меняет updater

### Исправление остановки туннеля

Остановка только `AmneziaWGTunnel$AmneziaVPN` оставляла в демоне состояние
подключения и маршруты исключений на физическом адаптере. Теперь updater сначала
отправляет штатную команду `deactivate`, которой пользуется GUI. Демон удаляет
свои исключения и разбирает туннель. Остановка служб остаётся резервным способом.

Временная служба WireGuard может исчезнуть между получением `ServiceController`
и ожиданием остановки. Код Windows 1060 в этом случае означает завершённую
остановку; ошибки доступа и другие ошибки не скрываются. Это поведение проверяют
регрессионные тесты без изменения настоящего VPN.

После полного удаления старого списка, установки свежего каталога и очистки
оставшихся старых маршрутов на исследованном компьютере все 944 ожидаемых
маршрута присутствовали в активной таблице. Подключение с новым списком заняло
17,433 секунды вместо 73,990; ошибок 5010 в новой попытке не было. Это измерение
одного компьютера, а не обещание такого же времени для всех пользователей.

### Компактный список

- Вместо снимка текущих интерфейсов записывает три устойчивых RFC1918-исключения.
  Они покрывают и будущую локальную подсеть после перезагрузки.
- Перед записью объединяет готовые сети и все известные IPv4 доменов.
  Убирает повторы, вложенные сети и сливает только полностью смежные блоки.
  Публичное IP-покрытие объединения при этом сохраняется.
- Не передаёт домены без IP: в исследованном логе они порождали `/999999`.
- Сохраняет последние рабочие DNS-ответы отдельно от свежих, поэтому повторные
  сбои DNS не стирают маршруты после перехода с доменных ключей на CIDR.
- Windows updater принимает до 2000 публичных маршрутов; автоматический выпуск
  ограничен 1000 маршрутами и только ручным каталогом. Превышение прерывает сборку.

В исследованном логе было 3407 уникальных маршрутов; их точное объединение —
1596 маршрутов. Это уменьшение нагрузки, а не обещание ускорения ровно вдвое.
Готовый IP-список из 1363 сетей уже был схлопнут: уменьшать его дальше без
изменения покрытия нельзя. Основной избыток был в сочетании сетей и доменных IP.

Ручные записи updater сохраняет. Они могут отдельно увеличивать нагрузку;
`-ReplaceAll` удаляет их только по явному выбору пользователя. Переход не требует
этого флага, если прежний список управлялся updater и его состояние сохранено.

Совпадение ручной записи с сетью из каталога не передаёт updater право удалить
эту запись: после последующего изменения каталога она остаётся ручной. Это
относится и к обновлению без изменения настроек. Для старого состояния, где
прежняя версия уже присвоила ручную запись, восстановить её происхождение
автоматически нельзя.

### Повторные запуски и восстановление

Установщик передаёт проверенный список и DNS-ответы первому применению через
временный файл. Поэтому предварительная проверка и применение не повторяют
скачивание и DNS. Входные данные проверяются заново, настройки Amnezia
перечитываются; файл старше 15 минут или с другими параметрами отклоняется.
Если за время установки истёк срок DNS, повторяется только DNS. В фоновую задачу
путь этого файла не записывается.

По умолчанию свежий DNS-кэш действует 6 часов — до очередного планового
обновления. В последние 5 минут этого срока updater уже запрашивает DNS заново:
иначе время завершения предыдущего запроса могло бы отложить обновление ещё на
6 часов. `-DnsCacheHours N` у installer и updater задаёт срок от 0 до 24 часов;
`0` отключает использование свежего дискового кэша, но сохраняет последние
известные адреса для работы при сбоях DNS. Это срок свежести обновлятора,
а не фактический TTL DNS-сервера. Передача свежих результатов между проверкой
и применением во время одной установки работает и с `-DnsCacheHours 0`.

Ошибка записи журнала после остановки VPN не пропускает попытку вернуть
соединение. При неполном восстановлении журнал и исходная ошибка сохраняются.
IPv6-диагностика выполняется после восстановления незавершённой операции;
`-RecoverOnly` не запускает сетевую проверку. Диагностика учитывает фактически
выбранный маршрут до контрольного адреса и сообщает о сбое этой проверки,
не делая вывода о недоступности всего IPv6 по одной точке.

## Применение и проверка

1. Обновите проект и повторно запустите `windows\install.ps1` в PowerShell от
   администратора, либо скачайте установщик из README. Одного скачивания новых
   списков недостаточно: старые установленные скрипты сами не заменяют свой код.
2. Установщик остановит старую задачу, восстановит незавершённую транзакцию,
   проверит новый скрипт и заменит установленную копию. При изменении маршрутов
   updater переподключит VPN с резервной копией настроек, если KillSwitch выключен
   или явно передан разовый `-AllowVpnReconnect`. При включённом KillSwitch без
   этого флага применение откладывается до остановки Amnezia пользователем.
3. В `%LOCALAPPDATA%\AmneziaRouteSync\status.json` проверьте
   `effective_route_count`, `redundant_routes_removed`, `unresolved_domain_count`
   и три диапазона в `local_subnets`. На следующем неизменившемся запуске должно
   быть `changed: false`.
4. Проверьте обычное переподключение, затем запуск Windows с задержкой на экране
   входа. Это проверяет именно исходную проблему; автоматические тесты не могут
   заменить перезагрузку реального компьютера.

Если частная сеть доступна только через Amnezia, используйте установщик с
`-NoLocalSubnets` и настройте точные исключения LAN вручную: полные RFC1918
диапазоны иначе исключат и эту частную сеть из Amnezia.

Для сводки включите логирование в Amnezia и выполните:

```powershell
python tools/analyze_amnezia_log.py --latest-connection --state "$env:LOCALAPPDATA\AmneziaRouteSync\status.json" "$env:APPDATA\AmneziaVPN.ORG\AmneziaVPN\log\AmneziaVPN.log" "C:\ProgramData\AmneziaVPN\log\AmneziaVPN-service.log"
```

Сводка содержит время рукопожатия и появления `connected`, количество ошибок,
повторов и компактных маршрутов. Ключи VPN, адрес сервера из строки подключения
и исходные строки лога не выводятся; счётчики повторно захватываемых маршрутов
могут содержать адреса локальной сети. `--latest-connection` выбирает последнюю
попытку; `--since` позволяет задать начало вручную. `--state` сравнивает число
исключений с планом updater. `excess_routes` обнаруживает избыток старых маршрутов;
совпадение счётчиков само по себе не доказывает совпадение покрытия. Анализатор
только читает файлы и не переподключает VPN. Исходные логи не публикуйте.

Изменения касаются Windows updater. На macOS по умолчанию уже применяется
схлопнутый IP-список без доменов; Windows-ошибка 5010 не доказывает ту же причину
задержек на macOS.
