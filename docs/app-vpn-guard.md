# Claude и ChatGPT/Codex только через AmneziaWG на Windows

Дополнительная защита для каталогов установленных Windows-приложений. Она блокирует их
исходящие соединения по IPv4 и IPv6, если выбранный Windows маршрут выходит через
любой интерфейс, кроме `AmneziaVPN`. Если интерфейса VPN нет, соединения запрещены.
Loopback внутри компьютера сохраняется. Политика других приложений не меняется.

Правила охватывают пути каталогов, включая будущие версии пакетов и новые EXE.
Добавление файла не требует сканирования или обновления политики: его первый
сетевой запрос уже подпадает под фильтр. Отдельные правила также сохраняют
идентичности обнаруженных работающих процессов.

Правила WFP постоянные: они продолжают действовать после завершения установщика
и остановки наблюдателя, загружаются службой BFE при запуске Windows. Наблюдатель
под SYSTEM обновляет разрешённый идентификатор интерфейса при переподключении.
Пока новый интерфейс не обнаружен, приложения остаются заблокированы. Замена
правил выполняется одной транзакцией: ошибка оставляет предыдущую политику.

## Установка

Нужны Windows 10/11, AmneziaWG с интерфейсом `AmneziaVPN`, MSVC и Windows SDK для
сборки. Для установки нужны права администратора. Подключите VPN и выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File windows\build-app-vpn-guard.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File windows\install-app-vpn-guard.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File windows\install-app-vpn-guard.ps1 -Install
```

Вторая команда показывает план. Установщик находит каталоги пакетов Claude и
ChatGPT/Codex, внутренних клиентов и текущие процессы. Виртуализированный путь
Claude Code определяется через Windows: отображаемый путь процесса может уже
не существовать, хотя процесс ещё работает.

Перед применением установщик проверяет настоящие WFP-фильтры на своём отдельном
процессе: отсутствие разрешённого VPN блокирует TCP по IPv4 и IPv6 с ошибкой
Windows `WSAEACCES`; разрешённый интерфейс сохраняет TCP-доступ по IPv4. Также
проверяется граница каталога и первое соединение нового переименованного EXE,
созданного после установки фильтра. Это
имитация отсутствующего VPN для тестового процесса, без отключения туннеля.
Она не заменяет испытание реальной перезагрузкой и захватом трафика приложений.

Код, конфигурация и команда удаления находятся в `%ProgramFiles%\AmneziaAppVpnGuard`;
обычные пользователи имеют только доступ на чтение. Задача
`Amnezia-App-VPN-Guard` запускает наблюдатель при старте Windows и входе пользователя.

## Границы защиты

- Правила относятся к выбранным **каталогам и процессам**, а не к любому коду с
  названием «Claude» или «ChatGPT». Открытые в другом браузере сайты, отдельные
  виртуальные машины и произвольные системные инструменты под эти правила не
  попадают. Внешний локальный прокси может сделать соединение от своего имени;
  loopback этой защитой не запрещён.
- Новые EXE и версии в выбранных каталогах защищены сразу. Перенос приложения
  в другое место или переход на другой пакет с иным именем потребует повторной
  установки. Правила не наследуются произвольными системными инструментами,
  которые приложение запускает из других каталогов.
- Пока служба BFE не запущена, эти пользовательские WFP-фильтры не активны.
  Отключение BFE, изменение защиты администратором и загрузка внешней ОС выходят
  за пределы этой настройки. Загрузка постоянных объектов описана в
  [Microsoft WFP](https://learn.microsoft.com/en-us/windows/win32/api/fwpmu/nf-fwpmu-fwpmprovideradd0).
- Защита рассчитана на AmneziaWG/WireGuard. Для Xray с локальным прокси нужна
  другая политика. Изменение имени VPN-интерфейса потребует переустановки с
  `-AdapterAlias`; до этого защищённые EXE не получат доступ через новый интерфейс.
- У приложения не будет прямого доступа и к российским исключениям, если Windows
  направляет их вне VPN. Остальные приложения сохранят прежний split tunneling.

## Проверка и удаление

В PowerShell от администратора:

```powershell
& "$env:ProgramFiles\AmneziaAppVpnGuard\app-vpn-guard.exe" --status
Get-ScheduledTask -TaskName Amnezia-App-VPN-Guard
```

Счётчики `persistent` и общего числа фильтров должны совпадать, `disabled` должен
быть нулём. Эти счётчики подтверждают наличие политики, а не историю сетевых
соединений. Ошибка региона сама по себе не подтверждает утечку домашнего IP.

Удаление только этой политики и её задачи, также от администратора:

```powershell
& "$env:ProgramFiles\AmneziaAppVpnGuard\install-app-vpn-guard.ps1" -Uninstall
```

Политика AmneziaVPN и другие правила Windows при удалении не затрагиваются.
