# Claude и Codex: защита от выхода мимо VPN

Частота обновления списка не гарантирует скрытие IP. Обновлятор устраняет один
конкретный риск: по умолчанию он не закрывает работающую Amnezia ради новых
маршрутов. Проверка идёт раз в неделю, в воскресенье в 12:00 местного времени.
Первая проверка выполняется при установке. Ручной запуск также не получает
автоматического разрешения на переподключение.

## Что изменено

- Если список тот же, VPN не трогается.
- Если GUI или туннель работают, новый список не применяется.
  Проверенный снимок сохраняется отдельно в `deferred-update.json`;
  последний применённый список и `status.json` сохраняются.
- При закрытых GUI и туннеле можно записать настройки для следующего запуска.
  Закрытие VPN само по себе не защищает другие приложения.
- Перед реальным применением или частичным rollback обновлятор штатно закрывает
  Claude и ChatGPT и проверяет завершение их процессов и helpers. Применение
  отменяется, если закрытие отклонено, истёк срок ожидания, клиент снова появился
  или остался Claude CLI. Принудительного завершения нет. Проверка неизменённого
  списка, обычная отсрочка и восстановление только подключения клиентов не закрывают.
- Обновлятор не открывает клиентов после операции. Их можно запустить вручную
  после проверки подключения VPN. На macOS `ChatGPT.app` может быть оболочкой
  Codex; этот вариант также охвачен. Если обновлятор запущен из защищаемого
  клиента, операция отменяется до закрытия приложений. Для применения нужен
  отдельный Терминал/PowerShell или фоновая задача.
- macOS может потребовать разрешение Automation для штатного завершения приложения.
  Отказ или недоступность Apple Events отменяет применение до отключения VPN.
- Разовые `--allow-vpn-reconnect` на macOS и `-AllowVpnReconnect` на Windows
  разрешают перезапуск, но не блокируют сеть. Нужна независимая защита до
  запуска команды. Флаги не сохраняются в расписании.
- Восстановление журнала не может автоматически остановить работающий VPN
  ради частичного rollback. Журнал сохраняется до возможности восстановления.
- Проверки перед записью и после неё обнаруживают запуск Amnezia во время
  обслуживания и сохраняют журнал при ошибке. Они не образуют общий lock с
  приложением: полностью исключить одновременный запуск одним `pgrep` нельзя.
  То же ограничение действует для повторного запуска Claude/ChatGPT: закрытие
  процессов не заменяет постоянный firewall и не запрещает ручной повторный запуск.

## Для строгой изоляции

Самая сильная практическая граница — отдельная рабочая среда, у которой есть
только VPN-выход. Например, VM с единственным сетевым адаптером к VPN-шлюзу;
у шлюза постоянный firewall разрешает наружу только выбранный VPN endpoint,
а трафик рабочей среды — только через туннель. При падении туннеля доступ
рабочей среды блокируется. Обычный NAT или bridged-адаптер VM такого свойства
не имеют. VPN endpoint берётся из выбранной конфигурации, без скрытого сервера
по умолчанию.

В этой среде должны работать Claude/Codex, браузер, локальные прокси и все
запускаемые ими `curl`, Python, Node и другие команды. Если приложение общается
с прокси или агентом вне этой среды, внешний процесс снова может выйти напрямую.
Для такого режима российские исключения также не должны давать рабочей среде
прямой выход.

Защита должна охватывать IPv4 и IPv6, TCP и UDP, DNS, запуск системы до VPN,
сон/пробуждение, смену Wi-Fi и штатное отключение VPN. DNS-резолвер рабочей
среды также должен быть достижим только через VPN; прямой DNS fallback запрещён.
Адреса VPN endpoint и его разрешение проверяются отдельно: физическое
подключение к самому VPN-серверу необходимо и не является скрытым от провайдера.

Для Windows проект содержит [постоянную WFP-защиту каталогов приложений](app-vpn-guard.md).
Она блокирует IPv4/IPv6 вне интерфейса VPN для охваченных EXE, но не наследуется
произвольными дочерними программами вне выбранных путей и не закрывает внешний
loopback-прокси. Для macOS аналогичная постоянная защита этим проектом не установлена.

[KillSwitch Amnezia](https://docs.amnezia.org/documentation/instructions/killswitch/)
защищает при неожиданном обрыве активного подключения; при ручном отключении
обычный интернет разрешён. Поэтому одной этой настройки недостаточно для
постоянного запрета доступа мимо VPN.

## Как проверять результат

Проверка одного IP-сайта подтверждает только выход конкретного запроса.
Нужен захват трафика на физическом интерфейсе и испытания подключения, штатного
отключения, сбоя туннеля/службы, смены сети и перезагрузки. Соединения защищённой
среды к внешним сервисам и DNS не должны появляться на физическом интерфейсе
в открытом виде; допустимы транспорт VPN и необходимая локальная сеть шлюза.
Тестовые запросы запускаются внутри защищённой среды, включая дочерние команды.
До такой проверки нельзя утверждать, что установленная система не допускает
утечки. Тесты обновлятора подтверждают поведение кода, а не сетевую изоляцию.

Абсолютной гарантии нет: администратор может отключить firewall, а уязвимость
системы или ошибка конфигурации может нарушить изоляцию. Скрытие IP также
не скрывает аккаунт, cookies, оплату и данные, которые пользователь сам отправляет.
