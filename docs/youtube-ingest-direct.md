# YouTube: отправка стрима напрямую на Windows

Опциональный профиль `-YouTubeIngestDirect` добавляет к RU Direct IPv4 серверов
приёма YouTube RTMPS: `a.rtmps.youtube.com` и `b.rtmps.youtube.com`, порт 443.
Эти адреса используются в [настройках OBS](https://github.com/obsproject/obs-studio/blob/master/plugins/rtmp-services/data/services.json).
Видеопоток может идти через провайдера, пока остальные назначения используют
обычную политику Amnezia. Доступность и достаточный upload нужно проверить на
своём подключении. Профиль не обходит фильтрацию провайдера.

## Проверка до изменения настроек

Из каталога проекта, в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File windows\update-amnezia-routes.ps1 -TestYouTubeIngest
```

Диагностика не записывает маршруты/реестр, не отключает VPN и не запускает эфир.
Она получает свежие DNS-ответы и проверяет до двух публичных IPv4 каждого сервера:

- `Direct` — сокет принудительно использует активный физический Ethernet/Wi-Fi
  с IPv4-маршрутом по умолчанию. При нескольких подключениях выбирается меньшее
  суммарное значение метрик интерфейса и маршрута; `-DirectInterfaceIndex N`
  позволяет выбрать конкретное подключение. VPN-интерфейс не принимается.
- `System` — обычный маршрут Windows. Он может уже идти напрямую по исключению;
  эта строка сама по себе не доказывает использование VPN.
- `OK` — проверены TCP, TLS с сертификатом и SNI, полный RTMP handshake.
  Ключ стрима не используется, команды публикации и видео не отправляются.
- `LocalAccessDenied` / `10013` — локальный запрет Windows/WFP, в том числе
  KillSwitch для адресов вне исключений. Это не результат проверки блокировки РКН.
- `Failed` — сбой на указанном этапе. Таймаут не позволяет однозначно отличить
  фильтрацию провайдера от сбоя сети или сервера.

Код завершения `0` означает, что хотя бы одна прямая проба прошла; `2` — ни одна.
Это не гарантия доступности всех DNS-адресов или достаточного битрейта. После
изменения профиля запускайте диагностику снова. При `10013` до применения
исключений недоступность прямого пути ожидаема.

## Включение

Сначала посмотреть план без изменений:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File windows\update-amnezia-routes.ps1 -YouTubeIngestDirect -DnsCacheHours 0 -DryRun
```

Установка профиля и его автообновления, из PowerShell администратора:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File windows\install.ps1 -YouTubeIngestDirect
```

Добавьте свои прежние параметры (`-Lite`, `-Source`, `-NoLocalSubnets`,
`-ServerIndex`, `-DnsCacheHours`), если использовали их: переустановка задаёт
аргументы задачи заново. Флаг YouTube сохраняется в фоновой задаче. Кэш DNS
обновляется по общей политике, по умолчанию каждые 6 часов; новые ответы заменяют
старые. При недоступности DNS остаются последние известные публичные IPv4.
Если для одного из серверов ещё нет адресов, применение останавливается до
изменения настроек. Более 32 IPv4 на сервер также не принимаются.

С включённым KillSwitch применение изменённого списка к работающему VPN
откладывается. Скрипт сохраняет эту защиту. Для заранее подготовленного разового
переподключения предусмотрен существующий параметр `-AllowVpnReconnect`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File windows\install.ps1 -YouTubeIngestDirect -AllowVpnReconnect
```

Он разрешает краткий перерыв VPN и защиты его KillSwitch при установке;
в фоновую задачу это разрешение не сохраняется. Подробнее —
[поведение KillSwitch](windows-killswitch.md). Установка задачи сама по себе не
подтверждает применение списка: проверяйте итог команды и диагностику.

В OBS:

1. Выберите сервис **YouTube - RTMPS** и основной либо резервный сервер,
   для которого прошла прямая проверка.
2. В расширенных настройках сети выберите **IP Family: IPv4 Only**.
   Привязку к адресу оставьте **Default**: путь выбирают маршруты Amnezia.
3. Если используете свой URL, сохраните имя хоста. Подмена его голым IP нарушает
   SNI/проверку сертификата, необходимых [YouTube RTMPS](https://developers.google.com/youtube/v3/live/guides/rtmps-ingestion).
4. Проведите закрытый тест 10–15 минут с целевым битрейтом, следите за потерянными
   кадрами сети OBS и состоянием потока в YouTube Studio.

Перед следующим эфиром можно принудительно обновить DNS обычным запуском updater
с `-YouTubeIngestDirect -DnsCacheHours 0` и прежними параметрами списка.
Учитывайте правило KillSwitch выше. Во время эфира не применяйте новый список:
смена маршрутов/переподключение способны оборвать поток.

## Границы и отключение

- Профиль относится к Windows updater. Общий каталог RU Direct и macOS не меняются.
- Исключения основаны на IP и действуют для **всех приложений и портов** на этих
  адресах. Google может обслуживать на них другие сервисы, поэтому строго отделить
  только видеопоток от Studio/чата этим механизмом нельзя. Весь Google или
  `*.youtube.com` в исключения не добавляется.
- DNS-ответы — снимок, не подписка на изменения адресов. Если OBS получит другой
  IP, отсутствующий в исключениях, соединение будет следовать обычной VPN-политике.
  Успешная проба другого IP этого не исключает.
- IPv6, обычный RTMP на 1935 и HLS этим профилем не настраиваются. Поэтому
  `YouTube - RTMPS` и `IPv4 Only` важны.
- Автоматического переключения Direct/VPN при потере битрейта нет. При проблемах
  остановите тест и вернитесь к обычной маршрутизации.

Для отключения переустановите задачу **без** `-YouTubeIngestDirect`, сохранив
остальные выбранные параметры. После успешного применения updater удалит свои
исключения YouTube, сохранив ручные записи и адреса, нужные основному списку.
При KillSwitch снятие исключений также может быть отложено до разрешённого
переподключения. Разовый запуск updater без флага снимает профиль лишь до следующего
запуска фоновой задачи, если в ней флаг остался.

`status.json` содержит `youtube_ingest_direct` и `youtube_ingest_addresses` для
последнего успешного применения. Поле `active_routes_verified: false` напоминает,
что запись реестра не подтверждает применение маршрутов самим клиентом.
